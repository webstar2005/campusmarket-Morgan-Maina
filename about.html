The project

About this build

CampusMarket is one running project for the whole semester. Each week adds one layer to the same app, so nothing is thrown away at the end of a topic.

What CampusMarket is

A marketplace where students buy and sell second-hand items to each other: textbooks, calculators, dorm fridges, desk lamps, bicycles and clothing. A catalog, a product page, a cart, student accounts and a checkout, all pointing at one shared set of product records.

It is deliberately a small system with the same moving parts as a real store, because every part maps to something in the course: static pages, client scripting, server scripting and a database.

Why the catalog is static right now

The server sends every page here exactly as it is stored in the folder, so every visitor sees the same eight listings. That is the starting point, not the finish line.

Static, Weeks 1–4

Hand-written HTML and one stylesheet. Listings live in the markup itself. No server-side language, no database, nothing to install.

Good for structure, semantics, layout and accessibility, and it is the version every team member can build alone.

Dynamic, Week 7 onward

PHP reads each request and queries MySQL, so listings come from a real table and the same page serves every student differently.

Sign-in, sessions, a cart that survives a page reload and orders all appear once the data is live.

How each week adds to it

The same project across fourteen weeks, one topic at a time.

Weeks 1–4
Static catalog: home page, product listing, category pages and a product page in plain HTML and CSS.
Weeks 2–5
Client scripting: live search, filters, sorting and cart totals calculated in the browser.
Week 6
CAT 1: the individual build is assessed and signed off before any team work starts.
Weeks 7–10
Server scripting and database: PHP pages, MySQL tables, registration, sign-in, sessions and a persistent cart.
Week 11
CAT 2: the merged team version is assessed against the full brief.
Weeks 12–14
Checkout, order management, seller tools, documentation and the final defence.

How the current pages are put together

Semantic HTML

One header, one nav, one main, one footer, one heading per page in order, and landmarks a screen reader can jump between.

One stylesheet

Colours, spacing and type sizes live as custom properties at the top of css/style.css, so a change there restyles every page.

No dependencies

No framework, no build step, no package manager. Open any file in a browser and it works, which keeps the focus on the course material.

Open source

The code is public

Every page in this build is committed to GitHub as it is written, so the history shows the project growing week by week. In Week 7 this repository becomes the starting point for the team version.
